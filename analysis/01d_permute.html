① 一句话回答TL;DR

permute 不搬数据,只重排"轴的顺序"。它不改变任何元素,只把 9 个维度换个排列方式(返回视图,零拷贝)。所以不要去追踪"哪个像素去了哪里"——那是吃力不讨好的思路。

正确的思考方式是给轴"分配角色":reshape 之后 9 个轴分两组——5 个"地址轴"回答"这个 patch 在图的哪个位置",(1×13×12×2×2 = 624);4 个"内容轴"回答"这个 patch 里面装了什么",(3×2×16×16 = 1536)。permute(1,3,6,4,7,0,2,5,8) 做的就一件事:把地址轴按从粗到细提到最外层,把内容轴整组压到最内层。这样最后一步 reshape(624, -1) 顺理成章——地址压扁成行号,内容压扁成列号,每个 patch 恰好占一行。

口诀:① 命名——reshape 出的 9 个数,先说清每个"是谁的轴";② 分组——5 个地址轴(在哪)、4 个内容轴(是什么);③ 排序——地址组按从粗到细抄下标 (1,3,6,4,7),内容组按 (通道,时刻,行,列) 抄下标 (0,2,5,8),拼起来就是 permute 的参数。

② 先给 9 个轴起名字(思考的前提)name the axes

scene.py :: _patchify 先把 (C, T, H, W) = (3, 2, 416, 384) 的整图 reshape 成 9 维——这一步把 H、W 各切成三段,每段获得一个专属轴:

# scene.py :: _patchify(237-252 行),以历史帧 384×416 为例
pixels = pixels.unsqueeze(1).expand(-1, 2, -1, -1)   # (C, T, H, W) = (3, 2, 416, 384)
patches = pixels.reshape(
    pixels.shape[0],          # 轴0 C     = 3    RGB 通道
    1,                        # 轴1 grid_t= 1    视频时间步(图像恒为 1)
    2,                        # 轴2 T     = 2    时间维(单帧复制)
    rows // 2,                # 轴3 GH    = 13   块行(26 行 ÷ 合并 2)
    2,                        # 轴4 MH    = 2    块内合并行
    16,                       # 轴5 PH    = 16   patch 内像素行
    cols // 2,                # 轴6 GW    = 12   块列(24 列 ÷ 合并 2)
    2,                        # 轴7 MW    = 2    块内合并列
    16,                       # 轴8 PW    = 16   patch 内像素列
)                              # → (3, 1, 2, 13, 2, 16, 12, 2, 16)
patches = patches.permute(1, 3, 6, 4, 7, 0, 2, 5, 8).reshape(rows * cols, -1)
# → (1, 13, 12, 2, 2, 3, 2, 16, 16) → (624, 1536)
旧下标名字大小角色组来历
0C3RGB 通道内容整图的通道维,reshape 没动它
1grid_t1视频时间步(图像恒 1)地址reshape 里写死的 1(视频路径 > 1)
2T2时间维(单帧复制)内容expand 出的时间维
3GH13块行(哪个 32×32 块)地址H=416 = 13×2×16
4MH2块内合并行(token 的上下半)地址merge_size = 2
5PH16patch 内像素行内容patch_size = 16
6GW12块列(哪个 32×32 块)地址W=384 = 12×2×16
7MW2块内合并列(token 的左右半)地址merge_size = 2
8PW16patch 内像素列内容patch_size = 16

H = GH×MH×PH = 13×2×16 = 416 ✓;W = GW×MW×PW = 12×2×16 = 384 ✓。reshape 本身只负责"切":H 切成 (GH,MH,PH),W 切成 (GW,MW,PW);它不管顺序合不合适——那正是 permute 的活。

③ 核心框架:地址组 vs 内容组address vs content

目标是 (624, 1536):624 行 = 624 个 patch,每行一个;1536 列 = 一个 patch 的全部内容。倒推回来——

行号 624 = 1(grid_t) × 13(GH) × 12(GW) × 2(MH) × 2(MW) ← 地址组乘积
列号 1536 = 3(C) × 2(T) × 16(PH) × 16(PW) ← 内容组乘积

所以 permute 的参数就是把旧下标按这个意图抄一遍:地址组 (1,3,6,4,7)(从粗到细:时间步 → 块行 → 块列 → 组内行 → 组内列),内容组 (0,2,5,8)(通道 → 时刻 → 像素行 → 像素列):

变换前(3, 1, 2, 13, 2, 16, 12, 2, 16)通道优先的 9 维视图 → permute 后(1, 13, 12, 2, 2, 3, 2, 16, 16)patch 寻址优先的 9 维视图 → reshape(624, 1536)地址→行,内容→列
为什么内容轴必须是最后四维? reshape(624, -1) 把"最外层起的 5 个轴"乘成行号、"最内层起的 4 个轴"乘成列号。只有当"一个 patch 的全部内容 (C,T,PH,PW) 在内存顺序上连续"时,切出来的每一行才恰好是完整的一个 patch 向量。permute 的全部意义就是达成这一点。

permute 参数的第 i 个数 p[i] 的含义:新张量的第 i 维 = 原张量的第 p[i] 维。悬停下面任意卡片,看它的"来路":

.permute(1, 3, 6, 4, 7, 0, 2, 5, 8)

悬停任意卡片:上排 = 旧轴(旧下标命名),下排 = 新位置(新第 0…8 位)。蓝 = 地址组,橙 = 内容组。

⑤ 最后的 reshape:谁快谁慢reading order

reshape(624, -1) 按行主序展开:新轴从左到右,左边的慢、右边的快。地址组内部顺序 (grid_t → GH → GW → MH → MW) 决定了 624 个 patch 的编号节奏:

地址轴变化速度对 patch 编号的影响
grid_t最慢(恒 0)图像路径不参与编号;视频路径时按时间步分段
GH → GW慢32×32 块按行优先扫描:扫完一行块,再下一行块
MH → MW最快每 4 个连续编号 = 同一个 32×32 块内的 左上→右上→左下→右下 4 个 patch
读法:patch 行号 k 拆开就是 k = ((gh×12 + gw)×2 + mh)×2 + mw——先定位块,再定位块内四分格。这就是 01 篇说的"每 4 个连续的 patch 恰好属于同一个 32×32 像素块,为 2×2 合并提前排好队":合并时把相邻 4 行拼起来即可,不需要再查找。

⑧ 常见疑问FAQ

Q1:能不能跳过 permute,直接 reshape(624, 1536)?

不能。reshape 只按当前内存顺序重新切分。变换前最外层是 C、T——直接压平的话,连续内存是"同一通道、同一时刻的全图 416×384 像素",切出的 624 行里每行是横跨整幅图的碎片,不是任何一个 patch。必须先把地址轴提到外层,让"一个 patch 的全部内容"在内存顺序上连续,reshape 才能"顺手"切成 (624, 1536)。

Q2:permute 会拷贝内存吗?transpose 和它什么关系?

不拷贝。permute 是 transpose 的推广( transpose(a,b) 只交换两维,permute 一次排任意多维)。它只重排 shape 和 stride(跨度表),返回视图、零拷贝。真正发生数据搬动的是后面那次 reshape(rows*cols, -1):因为 permute 后张量不连续,此时的 reshape 会隐式做一次 contiguous() 拷贝(用 .view 会直接报错,提醒你必须拷贝)。

Q3:grid_t 这个大小恒为 1 的轴,为什么存在?

为视频路径预留。视频输入时 grid_t = 帧数 ÷ 2(两帧一个时间步)> 1,图像/单帧路径固定为 1。有它,图像与视频共用同一套 reshape-permute-reshape 代码和同一套 ViT 权重,只是地址组多了一层"时间步"的分段。

Q4:和 01c 篇"1536 维的内部解剖"的下标公式什么关系?

permute 后内容轴顺序是 (C, T, PH, PW),reshape 展平后每个 patch 向量里第 (c, t, i, j) 个元素的一维位置就是 dim(c,t,i,j) = c×512 + t×256 + i×16 + j——这正是 01c 篇 ⑤ 逐段验证的公式。c、t 恰好是新坐标的第 5、6 位(内容组前两维):通道最外、时刻次之,所以解剖图上是 R/G/B 三大段、每段内再分两个时刻。

Q5:下次遇到别的 permute,怎么快速心算参数?

三步:① 给每个旧轴写名字、标组;② 确定目标形状最外层要谁(地址组,从粗到细)、最内层要谁(内容组);③ 把这些轴的旧下标按顺序抄成参数。反过来校验:参数列表必须是 0…8 的一个排列,且新 shape = 旧 shape 按参数重排后各组乘积分别等于目标行、列数。
