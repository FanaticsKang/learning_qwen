⓪ 太长不看TL;DR

疑问一回答:"自注意力对顺序不敏感"说的是注意力算子本身(不带任何位置编码时的本性)——它把输入当"一袋 token",打乱顺序,每个 token 的输出逐位不变。而"位置编码把位置编进去"说的是打了补丁之后的模型。两句话不矛盾:前者是本性,后者是补丁。特别地,Qwen 系 LLM 的输入端没有任何加性位置编码,RoPE 就是唯一的位置来源——拿掉它,模型真的就成"词袋"了。

疑问二回答:"在二维平面内旋转"= 把每个头里 Q/K 向量的维度两两配对,每一对坐标 (x₁, x₂) 构成一个抽象的二维平面;"位置对应的角度"= 位置 m × 该平面的转速 θᵢ;然后在这一对维度上执行标准二维旋转公式(只改方向、不改长度),Q、K 都转、V 不转。旋转的复合性(R(a)R(b)=R(a+b))使得打分 q·k 里公共的绝对角度自动抵消,只剩相对距离 n−m。动画见 §③、§④,代码见 §⑤。

① 问题一:自注意力为什么"对顺序不敏感"?有位置编码不就有顺序了吗?permutation invariance

你的疑问点到了关键:这两句话其实都成立,只是说的对象不同——

说法说的是谁含义
"自注意力对顺序不敏感"注意力算子本身(不带位置编码的裸机制)把输入 token 打乱,每个 token 的输出向量逐位不变(置换等变)——它把序列当"一袋 token"(bag of tokens),只看内容、不看排列
"位置编码把位置编进去了"加了补丁之后的模型位置编码(加性 PE 或 RoPE)正是为了打破上面的对称性而存在的——先有"不敏感"这个缺陷,才需要这个补丁

为什么裸注意力是"词袋"?一行数学

注意力(单头、省略缩放)的计算:Attention(X) = softmax(X·WQ·(X·WK)T/√d) · X·WV。注意每个 token 的输出是对全体 token 按内容相似度加权求和——求和不在乎排列顺序。用置换矩阵 P 写就是:

Attention(P·X) = P · Attention(X)   ← 输出只是跟着 token 挪位置,每个 token 自己的结果一个比特都不变

后果:没有位置信息时,"我打你"和"你打我"里每个字的输出完全相同——模型彻底无法分辨这两个句子。这就是"对顺序不敏感"的确切含义。

浏览器实时验证:一个 3-token 迷你注意力

设定:3 个字、4 维向量;为可读性取 WQ=WK=WV=单位阵并省略 1/√d 缩放(置换等变的结论与矩阵取值无关)。左右两种语序,下面实时算出每个字的注意力输出向量:

我 打 你 你 打 我
语序 A:我 打 你
语序 B:你 打 我

解读:关闭位置编码时,同一个字在两种语序下输出逐位相同(注意力权重也相同)——"词袋"实锤;打开位置编码后输出立刻不同——顺序信息被注入了。你的直觉"位置编码已经把位置编进去了"完全正确,但它是对模型的描述;"对顺序不敏感"是对裸算子的描述。

那 RoPE 在这件事里扮演什么角色?

位置编码有两大家族,你脑中"把位置加到 embedding 上"的模型对应第一行;Qwen-Drive 的 LLM 用的是第二行:

加性绝对位置编码旋转相对位置编码(RoPE)
注在哪输入端一次性:xm + pm,位置从第 1 层起和内容相加纠缠,经 24/32 层残差与 FFN 逐渐稀释每层注意力的 Q、K 上,层内临时施加;V 与残差流始终不含位置,内容与位置彻底解耦
打分依赖什么展开 q·k 后是绝对位置 i、j 与内容的混合项,不是干净的"相对距离"只依赖相对位置 n − m(§④ 证明),平移不变、外推友好
长度外推学习式有硬上限(训练多长就多长);正弦式外推效果一般相对性天然友好,还能调 base(NTK/YaRN 等长度扩展方案的基础)
谁在用原始 Transformer(2017)、经典 ViT(可学习 1D/2D)Qwen / LLaMA 等主流解码 LLM;Qwen 的 LLM 输入端没有任何加性 PE,RoPE 是唯一位置来源
所以 03 篇那句话的准确读法是:"自注意力本身对顺序不敏感"= 把 RoPE 拿掉之后,Qwen 的 LLM 里就不剩任何位置信息,此时随便打乱序列,每个 token 的输出都完全一样。RoPE 不是"锦上添花",而是这类模型感知顺序的唯一渠道。

② RoPE 的核心想法:把"位置"变成"角度"position → angle

RoPE(Rotary Position Embedding,旋转位置编码,Su Jianlin 2021)的一句话版本:token 的位置编号 m,被编码成"转角"——位置越靠后,它的 Q/K 向量被转过的角度越大。

角度 = 位置 m × 转速 θ    ⟹    位置 0 转 0°,位置 1 转 θ,位置 2 转 2θ,…… 位置 m 转 mθ

关键在"转速 θ"不止一种:每个注意力头的 Q/K 向量有 d 维(如 64 维),被切成 d/2 个"二维平面",第 i 个平面有自己的转速:

θi = 10000−2i/d,  i = 0, 1, …, d/2−1   (d=8 时恰好是 1、0.1、0.01、0.001 rad/位置)

这就是多频率设计,和"时/分/秒针"或里程表一个道理:

平面转速 θᵢ(d=8)转一整圈需要角色
平面 01 rad/位置≈ 6.3 个位置高频:分辨紧邻的精细距离
平面 10.1 rad/位置≈ 62.8 个位置中频
平面 20.01 rad/位置≈ 628 个位置低频
平面 30.001 rad/位置≈ 6283 个位置极低频:分辨很远的大尺度距离

真实模型 d=64(32 个平面),相邻平面转速比 = 10000−2/64 ≈ 0.75;最慢的平面要约 62,832 个位置才转完一圈,所以在实际序列长度内,"多针组合"的位置读数几乎不会重复。

伏笔:角度是可加的——先转 a 再转 b 等于一次转 a+b(旋转的复合性)。这保证了两个 token 各自旋转后在打分里相遇时,共同的绝对角度会抵消,只剩角度差——这是 §④ 的主角。

③ 问题二:"把每个 token 的 Q/K 向量按位置对应的角度在二维平面内旋转"是什么操作?2D rotation, animated

这句话拆开是三个动作:配对 → 定角 → 旋转。注意:所谓"二维平面"不是图像空间,而是 Q/K 向量内部每一对坐标张成的抽象平面(横轴 = 第 2i 维,纵轴 = 第 2i+1 维)。

动作具体含义式子
① 配对把每头的 Q(或 K)向量 d 维两两一组,切成 d/2 个"二维平面",每组就是平面上的一个点 (x₁, x₂)(x₁,x₂), (x₃,x₄), …
② 定角"位置对应的角度":第 i 个平面给位置 m 的 token 分配角度 m × θᵢ(θᵢ 是该平面的转速,见 §②)φ = m·θᵢ
③ 旋转在该平面内按标准二维旋转公式转动这个点——只改方向、不改长度;Q 和 K 都做,V 不做x₁′ = x₁cosφ − x₂sinφ
x₂′ = x₁sinφ + x₂cosφ

每个平面独立转各自的 m·θᵢ,一共 d/2 个平面同时转——等价于用一个块对角旋转矩阵左乘整个 Q/K 向量。

④ 为什么旋转之后,打分只剩"相对位置"?relative position, animated & proved

几何直觉:整体平移 = 刚体转动

注意力的打分是 q·k(内积)。二维平面上,q·k = |q|·|k|·cos(夹角)——只看两根箭头的夹角,不看它们各自朝向绝对坐标几度。位置 m 的 Q 被转了 mθ,位置 n 的 K 被转了 nθ,于是:

  • m、n 同时 +1(两个 token 一起往后挪):两根箭头一起再转一个 θ —— 整幅图刚体旋转,夹角不变 → 打分不变;
  • 只有 n +1(相对距离变了):夹角变化 (n−m)θ → 打分变化。

所以"绝对位置去哪了"的答案是:它进了公共的旋转量,在求内积时被减掉了。

代数证明:两行矩阵

设 R(α) 是二维旋转矩阵。位置 m 的 Q 与位置 n 的 K 在打分前分别被旋转:

qm = R(mθ)·q ,   kn = R(nθ)·k
qm · kn = qT R(mθ)T R(nθ) k = qT R((n−m)θ) k    ← 只剩 n − m
用到:R(a)R(b) = R(a+b)(旋转复合),R(a)T = R(−a)(逆转)。

其中 R(α) = [ [cosα, −sinα], [sinα, cosα] ]——正是 §③ 动画里那个旋转公式写成矩阵的样子。每个平面独立做一遍、再对平面求和,注意力打分就是:

score(m, n) = Σi=1..d/2 |qi|·|ki|·cos((n−m)·θi)    ——一个只以相对距离 n−m 为自变量的多尺度函数

可选的复数视角:把 (x₁,x₂) 视为复数 x₁+ix₂,旋转 = 乘以 eimθ;则 qm·conj(kn) = q·conj(k)·ei(m−n)θ,取实部即为打分,同样只含 m−n。论文 RoFormer 用的就是这个语言。

这个"距离函数"长什么样?

取一个特例(所有平面上 q=k=单位向量,d=32、base=10000),画出打分随相对距离 Δ 的曲线——本页载入时在你的浏览器里现算:

横轴:相对距离 Δ(0–128);纵轴:归一化打分 g(Δ) = (2/d)·Σᵢcos(Δθᵢ)。Δ=0 时最大(自己看自己最亮),总体随 Δ 衰减——RoPE 天然带"近处更相关"的局部性先验;同时低频平面保留了长程分辨力,曲线不会一刀切归零。随机 q/k 时均值趋 0、方差随 Δ 收缩,定性结论一致。

数值验证(页面载入时实时计算,d=8,随机固定种子)

随机取一对 Q、K,分别在不同 (m, n) 处旋转后求内积。前三行相对距离都是 3,只是把两个 token 整体平移——内积完全一致;第四行 Δ 变成 7,内积立刻不同:

mnΔ = n−m旋转后内积 q·k(10 位小数)结论

换任何种子、任何平移量,结论不变(浮点上误差 < 10⁻¹⁰)。这就是"打分只依赖相对位置"的机器可验证版本。

⑤ 代码实现与逐步验证implementation

下面按"频率表 → 角度表 → 旋转"三步给出 PyTorch 风格的最小实现(命名与 HF/Qwen 的 apply_rotary_pos_emb 对齐),再给一段可独立跑通的验证脚本:

# ── 1. 频率表:每个二维平面的"转速" ─────────────────────────────
# head_dim 维向量 → head_dim/2 个旋转组;第 i 组角速度 θ_i = base^(-2i/head_dim)
def build_rope_cache(seq_len, head_dim, base=10000.0):
    inv_freq = 1.0 / (base ** (torch.arange(0, head_dim, 2).float() / head_dim))
    t     = torch.arange(seq_len).float()            # 位置 m = 0, 1, 2, …, L-1
    freqs = torch.outer(t, inv_freq)                 # 角度表 [L, d/2]:第 m 行 i 列 = m·θ_i
    emb   = torch.cat((freqs, freqs), dim=-1)        # 成对维度复制一份(HF 约定,见下)
    return emb.cos(), emb.sin()                    # cos[m, j], sin[m, j]

# ── 2. 旋转:把每对维度 (x_j, x_{j+d/2}) 当成二维平面上的点转 m·θ ──
def rotate_half(x):                      # x: (B, n_head, L, head_dim)
    x1, x2 = x.chunk(2, dim=-1)              # 前一半、后一半配对
    return torch.cat((-x2, x1), dim=-1)

def apply_rope(x, cos, sin):             # 只用于 Q 和 K;V 不旋转!
    return x * cos + rotate_half(x) * sin
# 展开(θ = 该平面对位置 m 的角度):
#   x_j'     = x_j  ·cos(mθ) − x_{j+d/2}·sin(mθ)
#   x_{j+d/2}' = x_{j+d/2}·cos(mθ) + x_j  ·sin(mθ)      ← 正是二维旋转公式

# ── 3. 在注意力里的位置(HF/Qwen 风格)───────────────────────
# q, k: (B, n_head, L, head_dim);cos, sin: (L, head_dim) 按位置对齐后广播
q, k = apply_rope(q, cos, sin)                      # 每层注意力内:QKV 投影之后、打分之前
attn = (q @ k.transpose(-2, -1)) / math.sqrt(head_dim)
# 因为 K 已含位置,KV 缓存里存的就是旋转后的 K —— 一次旋转,终身复用
两种"配对"约定,数学等价:论文按相邻维度配对 (x₁,x₂)、(x₃,x₄)…;HF/Qwen 实现按前后半配对 (x₁, x1+d/2)、(x₂, x2+d/2)…,所以代码里你会看到 rotate_half 和 cat(freqs, freqs) 这种写法——只是把"哪些维度组成一个平面"重排了一下,旋转的数学一模一样。读 Qwen 源码遇到 rotate_half 不要懵。

独立验证脚本:亲自确认"只依赖相对位置"

import torch, math
torch.manual_seed(0)
d   = 8
inv = 1.0 / (10000 ** (torch.arange(0, d, 2).float() / d))   # θ = [1, 0.1, 0.01, 0.001]

def rot(v, m):                        # 把 d 维向量 v 的每个平面各转 m·θ_i(相邻配对版)
    ang = m * inv
    c, s = ang.cos(), ang.sin()
    o = torch.empty_like(v)
    for i in range(d // 2):
        o[2*i], o[2*i+1] = v[2*i]*c[i] − v[2*i+1]*s[i], \
                               v[2*i]*s[i] + v[2*i+1]*c[i]
    return o

q, k = torch.randn(d), torch.randn(d)
print(rot(q, 2)  @ rot(k, 5))     # ← Δ = 3
print(rot(q, 17) @ rot(k, 20))    # ← Δ = 3,与上一行分毫不差
print(rot(q, 41) @ rot(k, 44))    # ← Δ = 3,仍然相同(整体平移了 39)
print(rot(q, 2)  @ rot(k, 9))     # ← Δ = 7,不同了(相对距离变了)

实现层面的三个要点(面试/读码常考):
  • 只有 Q、K 被旋转,V 不转——"内容"不掺位置,位置只决定"谁关注谁"(打分),不改变"被搬运的信息"本身;
  • 每层都重新转一次,但 cos/sin 位置表只算一次、全部层共用(这就是 03 篇说的 _rope_positions 算出 [3, batch, seq_len] 的那张表);
  • KV 缓存里存的是已旋转的 K—— causal 解码下 K 每个位置只算一次,Qwen-Drive 的 Planning Expert 直接读缓存,位置信息已经在里面了。

⑥ 回到 Qwen-Drive:同一套旋转,三种"位置轴"2D RoPE & M-RoPE

RoPE 的"位置 m"不一定是整数序号——任何能算出"位置数值"的东西都能喂给同一套旋转机制。Qwen-Drive 里用了两次,位置结构不同:

ViT 内(第 1 次注意力)LLM 内(第 2 次注意力)
位置轴行 h、列 w(2D RoPE)时间 t、行 h、列 w(M-RoPE 多模态 RoPE)
旋转组分配头维度按行/列两组转速(实现细节以权重为准)mrope_section = [11, 11, 10]:32 个旋转组 = 11 组跟 t、11 组跟 h、10 组跟 w(共 64 个旋转维/头)

⑦ 常见疑问 FAQfaq

Q1:角度转一圈 2π 就回去了,位置多了会不会"撞车"?

单个平面确实周期重复(周期 = 2π/θᵢ),但 32 个平面像"时分秒针"联合计时,联合周期是天文数字;d=64、base=10000 时最慢的平面要约 62,832 个位置才转一圈。更本质地,打分只依赖相对差(§④),绝对角度即使重复,也不影响"相隔多远"的判读。

Q2:为什么 base = 10000?

base 决定转速表的下限:最慢 θ = 10000−(1−2/d) ≈ 1/10000 rad/位置。base 越大,慢针越慢,可分辨的距离越长、但近距离的精细度下降。长度外推方案(NTK-aware scaling、YaRN)本质就是在推理时放大 base、重新拉开转速表。

Q3:为什么不旋转 V?

V 承载"内容",参与加权求和后进入残差流、FFN 和下一层;若旋转它,位置信息会混进内容表示,且每层累积。只转 Q、K 让位置只影响打分(谁该关注谁),内容通路保持干净——这就是 RoPE"内容与位置解耦"的设计。

Q4:RoPE 编码的是相对位置,那"绝对位置"信息哪去了?

确实几乎没有了——打分对整体平移不变。语言任务主要依赖相对结构(短语内部距离、句间距离),所以够用;而因果解码的自回归训练方式也让模型在实践中对绝对位置的需求进一步降低。这是设计上的取舍,换来的是外推能力和干净的相对几何。

Q5:Qwen 的 LLM 输入端还有别的位置编码吗?

没有。embedding 查表只有内容,RoPE 是唯一位置来源(呼应 §①:拿掉 RoPE 就真成"词袋")。ViT 端同样用 RoPE(2D 版),不用经典 ViT 的可学习加性位置参数。
