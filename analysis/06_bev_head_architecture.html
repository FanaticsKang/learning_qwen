① 图 3(a) 说了什么:你的理解对,补两个精确化

论文图 3 原文说明:"(a) The BEV perception head fuses voxelized vision encoder features with a feature pyramid of VLM outputs." (BEV 感知头把体素化的视觉编码器特征与 VLM 输出的特征金字塔融合。)

对照你的两条通路,理解完全正确,只补两处精确化:

你的描述精确化
原始图像 → Vision Encoder(ViT)→ BEV Transformer对。但 ViT 特征不是直接进注意力 —— 它先经 UVTR 深度视图变换变成 3D 体素、再压成 BEV token,加到 BEV query 上作为几何先验(详见 ④)。
Vision Encoder → Qwen3.5-4B → BEV Transformer对。实际抽取的是 LLM 最后一层的 image-token 隐状态(即 "VLM 输出"),经一个 4 尺度适配器变成特征金字塔,作为 BEV Transformer 交叉注意力的 key/value(详见 ⑤)。
为什么是两路?ViT 特征空间分辨率高(16 px/格)但语义浅,适合估深度、撑几何;VLM 输出经过 32 层语言模型,语义强但空间粗(32 px/token)。感知头让前者供"骨架"、后者供"理解",在 BEV Transformer 里汇合。

④ 感知流:UVTR 做了什么

这一路回答"东西在哪"。三步(细节见 04/05 篇,这里只摆架构角色):

步骤机制维数变化给后续留下什么
① 估深度DepthNet(3×残差块 + ASPP):每格输出 118 档深度概率,无深度监督[256,32,56] → [118,32,56]方向 + 距离的可能性
② 撒进 3D视锥格网(56×32×118 地址表)+ fused kernel 散射累加:D × F 沿射线入座→ [256, 200, 200, 16]保高度的 3D 几何特征(ego 系)
③ 兵分两路出路一:16 层拼通道 + 1×1 卷积压成 BEV token;加到 BEV Transformer 的 query 上。出路二:体积原样留给占用分支做 concat 融合[256,16,200,200] → [40000,256];体积另存几何先验 + 高度证据
为什么 query 要加它?可学习的 BEV embedding 初始是"无知识的白纸";加上 UVTR token 后,每个 BEV 格自带"该看哪个相机、看哪块图像"的几何暗示,注意力收敛更快更准。这是图 3 说的 "voxelized vision encoder features" 的归宿。

⑤ 语言流:VLM 特征金字塔怎么来

这一路回答"东西是什么"。同一个 ViT 前向的 patch 特征,经 merger 走完整个 VLM,再被抽回来:

抽取方式(代码实证):感知模型跑一次完整 VLM 前向(output_hidden_states=True),取最后一层隐状态过 final norm,再按 image-token 位置切片、reshape 回 [N, 28, 16, 2560] 网格(modeling_perception.py)。感知流水线只有当前环视帧(没有历史帧),切片只保留当前相机的 token。

2560 维的语义特征对像素级采样太粗(一格 32×32 px),于是 SimpleFPN 适配器做两件事:降通道(2560 → 256)和造金字塔(×4/×2/×1/×0.5 四个尺度)。远处的物体在图里只占几格 —— 在 112×64 的细尺度上正好采得到;近处大物体在 14×8 的粗尺度上一步看全。

尺度形状一格对应擅长
×4[256, 112, 64]8 px远处小物体
×2[256, 56, 32]16 px中景
×1[256, 28, 16]32 px(token 原生)常规
×0.5[256, 14, 8]64 px近处大物体 / 全局语境
为什么用 LLM 输出而不是 ViT 输出做语义?image-token 隐状态已经吸收了整段多模态上下文(视野序列、导航指令、历史轨迹的注意力)—— 它是"理解过"的特征。这正是图 3 说的 "feature pyramid of VLM outputs",而不是 vision encoder outputs。

⑥ BEV Transformer 做了什么

它是两路的汇合点:输入是"加了 UVTR 几何先验的 BEV query"(40000×256)和"VLM 特征金字塔"(4 尺度 key/value),输出是统一的 BEV 表征 bev_embed [40000, 256]。编码器共 6 层,每层三步:

层内步骤机制关键参数(代码核对)
① 时间自注意力 BEV 格之间互看,平滑邻近格的特征。原版 BEVFormer 在此融合上一帧 BEV(时序);本感知头严格单帧,prev_bev 为空,退化为普通 BEV 自注意力(docs/perception.md 明说与评测一致) 8 头 × 256 维;参考点 2D
② 空间交叉注意力
(核心)		 每个 BEV 格在 z 向立起 4 个 3D 参考点(柱内 4 层),经 ego2lidar → lidar2img 投影到每台相机 —— 投影出界的相机直接 mask 掉(只看得到它的相机,即论文 Ω(p) 的注意力版),再在 4 尺度金字塔上做可变形采样:每处学一组偏移 + 权重,加权取回 VLM 语义 8 头;4 尺度 × 每头 8 点;采样点由网络预测(非固定网格)
③ FFN 逐格两层前馈网络,消化采样来的信息 256 → 512 → 256,Dropout 0.1

一图看懂:①②③ 各自从哪里进场面

与 UVTR 的分工一句话:UVTR 是"查表式"几何搬运 —— 按深度概率把特征搬到该在的体素,快而准,但每个体素只见过自己那一台相机的局部信息;BEV Transformer 是"注意力式"语义汇合 —— 每个 BEV 格主动向所有有效相机的多尺度 VLM 特征提问,把语义、多视角、多尺度一次融齐。几何先验从 UVTR 来,语义证据从 VLM 来,最后谁说了算由注意力权重决定。
为什么单帧还要叫"时间"自注意力?训练好的权重是在时序设置下学的(结构带 num_bev_queue=2 的队列接口);单帧推理时队列退化为当前帧自己(stack([query, query])),输出与评测路径严格一致 —— 结构保留是为了权重兼容。

⑦ 三个输出头:同一份 bev_embed 的三种读法

7a · 3D 检测(900 个 query 问 BEV 要答案)

可学习 object query [900, 512](拆成内容 + 位置两半),位置半经 Linear(256→3)+sigmoid 变成 ego 系 3D 参考点;6 层 DETR 式解码器在 bev_embed 上迭代精修;每层接分类分支(7 类)与回归分支(code_size=10:位置 + 尺寸 + 朝向 + 速度);NMSFreeCoder 按类去重,最多输出 300 框。训练用论文式 (4):每层 2·focal + 0.75·ℓ₁ 求和。

7b · 占用栅格(两路特征的物理融合)

bev_embed 的 256 通道被重排成 16 通道 × 16 层高的 3D 体积 [16, 16, 200, 200],重采样到占用网格(nuScenes 80×80×6.4 m / nuPlan 100×100×8 m,均 200×200×16);UVTR 体素体积同样经 Conv3d(256→16)重采样后与之 concat(32)→ Conv3d 压回 16 残差融合 → 3D U-Net 细化(16→32)→ 线性头出 10 类(7 类障碍物 + 可行驶区域/背景/空)。训练用式 (5):100·focal + MonoScene 几何/语义亲和 + Lovász(FlashOcc 风格)。

这正是"保留高度"的兑现处:BEV embedding 的高度维只是通道重排的产物,而 UVTR 体积的高度是真 3D 几何 —— 占用的"哪一层有东西"主要由它提供。

7c · BEV 建图(裁一块,单独分割)

BevFeatureSlicer 从 bev_embed 裁出车周 60 m × 30 m(0.15 m/格 → 400×200),MapSegEncode(resnet18 干 + U-Net 上采样)出 6 类栅格。训练 100·focal + Lovász。

⑧ 分工总结:每个模块一句话

模块职责(一句话)输入 → 输出
Vision Encoder(ViT)把像素变成统一的视觉特征,供两路共用[3,512,896] → [56×32, 1024]
merger + Qwen3.5-4B给视觉特征注入多模态语义理解[448, 4096] → [28×16, 2560]

⑨ 常见疑问

Q1: 感知头会改变 VLM 吗?
A: 不会。ViT 和 LLM 的权重原封不动(推理时甚至开着 no_grad 跑前向),感知头只通过 hook "旁听"两处特征 —— 合并前的 patch、LLM 末层隐状态。这正是论文强调的 "without changing the VLM architecture";训练阶段 1 冻结 ViT+VLM、只训感知头。
Q2: 两路能不能只用一路?
A: 架构上可以,精度上吃亏:只用 UVTR,几何对但语义浅(分不清锥桶和施工牌的细微类别);只用 VLM 金字塔,交叉注意力要自己摸索 2D→3D 对应,且占用没有真高度证据。两路并用的消融逻辑就是图 3 把两者画成并联的原因。
Q3: BEV Transformer 和 UVTR 是不是功能重复(都在做 2D→3D)?
A: 机制互补而非重复。UVTR 用确定性几何(深度分布 + 标定)搬运,产出带强几何先验的 BEV token;BEV Transformer 用学习到的注意力采样,决定"这个鸟瞰格的语义最终听几台相机、几个尺度的"。前者给初值和高度,后者做全局语义表决。
Q4: 为什么检测融合用"加法",占用融合用"concat+卷积"?
A: 加在 query 上是最轻的先验注入:让 BEV 格自带几何暗示,但不过度约束注意力;占用则必须逐体素保留两份高度证据再融合,concat+Conv3d 让网络自己学配比 —— 高度信息经不起"加法折叠"。
Q5: 单帧推理,时序注意力白带了吗?
A: 结构是训练时定下的,推理单帧时它退化为普通自注意力(官方文档明说与评测路径一致)。保留结构是为了严格复用训练好的权重;若未来恢复多帧输入,无需改结构即可启用时序。
Q6: ViT 的 24 层是并联还是串联?每个 patch 一个 ViT 吗?
A: 串联。第 1 层输出是第 2 层输入,依次到第 24 层 —— "depth = 24" 即层数(与 LLM 的 32 层同理),推理时一次前向顺序跑完,层间没有循环。同时所有 patch 共享同一个 ViT:56×32 = 1792 个 patch 拼成序列过同一套权重,层内注意力让每个 patch 互相看见 —— 不存在"每个 patch 一个网络"。
Q7: 896×512 是当前帧吗?和历史帧呢?
A: 感知头是严格单帧模型,没有历史帧 —— 896×512 是"当前时刻环视 6/8 台相机"各自固定的输入分辨率(感知权重训练时的固定布局)。历史帧/当前帧之分属于 03 篇的规划流水线(12 帧动态分辨率:历史 384×416、当前 720p 档)。两套数字互不换算,对照表见 ① 节。
Q8: 规划 VLM 只用前向 3 视图,后向相机的内容没进"那个 VLM",BEVFormer 的后向格子岂不是没有 K/V?
A: 两条流水线不能混:BEVFormer 的 K/V 来自感知路自己的 VLM 前向 —— 那次前向吃的是全部 6/8 个相机(896×512),后向相机的隐状态同样变成金字塔 K/V;空间交叉注意力的投影 mask 再保证每个 BEV 格只从看得见它的相机采样(后向格子采后向 K/V)。"只用前向 3 视图"是规划路的事,它的输出(语言/轨迹)根本不进 BEVFormer。
