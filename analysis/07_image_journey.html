① 同一画面,两张"入场照"(4:3)

t-0s 时刻,如果前视相机拍到一张 1440×1080 的原始画面(4:3),它在系统里有两份 resize 后进入模型:

1. VLM 一份(smart_resize 保长宽比 → 当前帧 1088×800);
2. 感知头一份(拉伸到固定 896×512)。

另外,VLM 还需要 9 个历史时刻的画面(480×352)。注意 VLM 每次进的不止一台相机:6/8 个相机里只有 3 个前向视图(前视 / 左前 / 右前)进 VLM,每个视图取 4 个时刻(3 个历史时刻 + 当前),共 12 帧;感知头则用全部相机、只取当前一帧。

三条长宽比各不相同,都是设计使然:
① VLM 路:smart_resize 保持原图比例 —— 原图 1440×1080 → 1088×800(≈1.36)/ 480×352(≈1.36),只吸附到 32 的倍数并压进像素预算;
② 感知路:拉伸到训练布局 896×512(1.75 ≈ 16:9 的 nuScenes/nuPlan 相机),不保比。

② 总览数据流(只画感知路;Qwen3.5-4B 为黑盒)

当前环视 × 6/8 相机t-0s 单帧 · 拉伸到训练固定布局896×512 ⚠ 悬停看差异
▼ 6/8 帧拼成一条序列,同时过
Vision Encoder —— ViT(24 层串联,全部 patch 共享权重) 切 16×16 patch → 每 patch 编码成 1024 维向量,patch 数量不变(token 由后面的 merger 合并产生) 56×32 = 1792 patch × 1024
▼ 主干:merger(2×2 合并,1024×4 → 2560)→ 🔒 LLM(32 层)→ 隐状态 —— 一条主干,两个取材点
取材点① —— 核心:UVTR 深度视图变换 merger 入口取合并前细格(56×32×1024),不经合并、不经过 LLM → 深度 + 视锥池化(④ 详解) → [256,16,200,200] → BEV token [40000,256]
取材点② —— 核心:Qwen3.5-4B(LLM) merger 出 448 token × 2560/相机,过完 🔒 32 层 LLM,取末层隐状态 → 4 尺度金字塔 = BEVFormer 的 K/V
↘ 取材① = BEV token,加进 query   ↙ 取材② = K/V
BEV Transformer(BEVFormer 编码器 × 6 层) query = 可学习 embedding [40000,256] + 取材① token · K/V = 取材② 金字塔 bev_embed [40000, 256]
↙ 检测解码 占用融合 建图裁剪
3D 检测900 query → 6 层解码≤300 框 · 7 类
占用栅格BEV 重排 + UVTR 体积融合 → 3D U-Net[10, 200, 200, 16]
BEV 建图裁 60×30 m → U-Net[6, 200, 400] @0.15 m
LLM 在哪里?它在主干上:ViT 之后先 merger(2×2 合并 → 448 token × 2560/相机),再进 🔒 LLM。取材点① 在 merger 入口,所以 UVTR 不经过 LLM;K/V 取自 LLM 末层的隐状态 —— 几何、语义各取一处,互不干扰。
读图要点:每个框只标数据此刻的尺寸 —— 图像框 896×512,ViT 后 1792 patch × 1024,merger 后 448 token × 2560/相机,UVTR 后 [256,16,200,200],BEV token [40000,256];⚠ 悬停看与 VLM 输入(规划路)的差异。规划路(12 帧进 VLM → 轨迹)不在此图;其入场尺寸见 ①。

③ 感知路的尺寸账:896×512(像素 → patch → token)

同一段 896×512 的画面,在 ViT 前后经历"像素 → patch → token"三次计数变化 —— 图像尺寸不变,网格逐渐变粗(同一张图,用的格子越来越少、越来越大):

阶段网格数量每单元去向
原始像素896 × 512458,752 px1 个像素—
ViT patch(16×16)56 × 321792 个 × 1024 维16×16 px 的内容取材①:不合并 → UVTR
merger 2×2 → token(32×32)28 × 16448 个 × 2560 维/相机32×32 px 的语义取材②:过 LLM → K/V
一条主干、两个取材点(再强调):主干 = ViT → merger(2×2 合并)→ 🔒 LLM;取材点① 在 merger 入口拿不合并的 1792 个细格去 UVTR,取材点② 在 LLM 末层拿 448 个 token 的隐状态去 K/V。

④ UVTR 前后 —— 从图像平面到 BEV 空间

阶段形状所在空间一格的物理含义
UVTR 进入前[256, 32, 56]图像平面(896×512,7:4 拉伸)16×16 px 的画面内容
中间:视锥[256, 56, 32, 118]图像方向 × 深度(2.5D)"该方向、该距离"的候选点
UVTR 之后[256, 16, 200, 200]自车 3D 空间(102.4×102.4×10.4 m)0.512×0.512×0.65 m 的物理格
压成 BEV token[40000, 256]自车鸟瞰平面(200×200)0.512×0.512 m,16 层高度已拼进通道

⑤ BEV Transformer 的 Embedding / query / K·V

② 的来源接回 ⑤:UVTR 体积 [256,16,200,200] 把 16 层高度拼进通道([4096,200,200]),经 1×1 卷积压回 256、展平成 [40000,256],与可学习 embedding 同构相加 —— 一张图的"几何影子"从此写进每个 BEV 格的问题里。
疑问:后向相机没进"那个 VLM",后向 BEV 格岂不是没有 K/V?——不会,这里不能把两条流水线混在一起:
① "VLM 只用前向 3 视图"说的是规划路 —— 它的输出是语言/轨迹,根本不进 BEVFormer,谈不上缺 K/V;
② BEV Transformer 的 K/V 来自感知路自己的那次前向:黑盒这一次吃的是全部 6/8 个相机(896×512),后向相机的 image-token 隐状态同样变成金字塔里的 K/V —— 后向 BEV 格有对应的 K/V 可采;
③ 空间交叉注意力的投影 mask 再保证"各取各的":后向格子只采后向相机的 K/V,前向格子只采前向的,互不越界、互不缺失。
