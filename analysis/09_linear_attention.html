1. 回顾:标准 Softmax 注意力在做什么,贵在哪里Softmax Attention

给定查询 Q、键 K、值 V(均来自同一序列的投影,形状都是 N × d,N 是 token 数,d 是每头维度),缩放点积注意力为:

Attention(Q, K, V) = softmax( Q KT / √d ) · V

直观理解:第 t 个 token 拿自己的 qt 去和**所有历史** k1..t 逐一打分,分数经过 softmax 变成一组"精确分配"的权重,再加权求和所有 v。它本质上是一个精确的、内容寻址的键值数据库:任意一个历史 token 只要 key 够独特,就能被无损地检索回来。

逐行拆解:对一个查询,softmax 到底算了哪三步

把第 t 行(第 t 个查询)单独拎出来,一次注意力检索是严格的三步 —— 演示 1 用 N=4、d=3 的真实数字把每一步都算给你看:

① 打分    st,i = qt · ki / √d     (i = 1…N,一个查询得 N 个分数)
② 归一化   at,i = exp(st,i) / Σj=1…N exp(st,j)
③ 加权求和   yt = Σi=1…N at,i vi
①③ 各要扫一遍 N×N(合计 O(N²·d) 次乘加);② 逐元素 exp + 逐行求和也是 O(N²)。三步全都离不开那个 N×N 的中间量 —— "贵"就贵在这里

对应到代码就是 10 行 NumPy(单头、无 batch,注释里的 ①②③ 与上式一一对应,可直接跑):

import numpy as np def softmax_attention(Q, K, V): # Q, K, V 形状都是 (N, d):单头、无 batch,与上面公式一一对应 d = Q.shape[-1] # ① 打分:S 是 (N, N) —— N² 个分数,平方账从这里开始 S = Q @ K.T / np.sqrt(d) # 数值稳定:每行减去最大值,防止 exp 上溢,不改变 softmax 结果 S = S - S.max(axis=-1, keepdims=True) # ② 逐元素 exp:大分数被指数级放大,小分数趋于 0 E = np.exp(S) # ③ 逐行归一化:每行除以自己的行和,权重和恰为 1 A = E / E.sum(axis=-1, keepdims=True) # ④ 加权求和:每个输出行都是全部历史的凸组合 —— 又扫一遍 N×N return A @ V

🧮 演示 1 · softmax 内部:打分 → exp → 归一化 → 加权求和(数字全部真实计算)

查询行 t:

选中一个查询行后逐步播放,观察第 t 行如何从"N 个原始分数"变成"一组和为 1 的权重"再到"加权输出"。拖大 β:权重迅速向最像的那个键集中成尖峰 —— 这就是 exp 带来的精确检索;把 β 调到最小,分布摊平成近乎均匀的"平均脸" —— 那恰是 §2 线性注意力去掉 exp 之后的世界。而无论 β 多小,打分和加权都要让每个查询扫过全部 N 个历史:O(N²) 躲不掉。

成本:问题全在 softmax 上

先算 QKT 得到 N × N 的分数矩阵,再对它逐行做 softmax,然后乘 V:

项目标准注意力说明
训练时间复杂度O(N²·d)两个 N×d 矩阵相乘(打分)再乘回 V
训练显存O(N²)需要保存 N×N 分数矩阵的激活(FlashAttention 用分块重算规避了显存,但计算量不变)
推理状态(KV Cache)O(N·L·h·dh)每层都要缓存全部历史的 K、V;序列越长缓存越大
推理每 token 计算量O(N·d)/层生成长度走到 N 时,每个新 token 都要和全部历史打一遍分

注意 softmax 的角色有两个:① 归一化(每行权重和为 1,构成凸组合);② 非线性化(exp 让"最像的键"吃掉几乎全部权重,产生尖峰式的精确检索)。这两个好处都有代价:exp 把"打分"和"加权求和"两个步骤焊死在一起,你无法先对历史做任何形式的"汇总压缩",只能对每个查询都把历史从头比一遍。(演示 1 的 β 滑杆可视化的正是角色 ②:β 越大分布越尖;β→0 时退化成均匀平均。)

GQA 也是省 KV Cache 的,但省的不是这份钱:标准注意力里 16 个 Q 头共享 4 组 KV 头(Grouped-Query Attention),KV cache 直接 ÷4——但打分仍然是 O(N²),每个 token 仍要读全部历史。GQA 是"把缓存变薄",线性注意力是"把缓存变成固定大小"。

2. 线性注意力的核心思想:利用结合律,先"求和"再"查询"Linear Attention

2.1 一个被 softmax 挡住的等价变换

不带 softmax 的打分加权其实可以做矩阵乘法结合律的变形:

(Q KT) V  ≡  Q ( KT V )

左边:N×N 中间矩阵(贵)。右边:KTV 是 d×d 的**小矩阵**(便宜,只跟维度有关、与 N 无关)。线性注意力的一切都源于这个括号位置的移动。

但标准注意力不能这么变——softmax 作用在 N×N 矩阵的每一行上,无法拆成"先算 KTV"的形式。所以线性注意力的第一步是:把 softmax 这个核函数换掉。Katharopoulos et al.(2020)提出用逐元素特征映射 φ(·)(如 elu(x)+1,恒为正)近似指数核:

Attnlin(Q,K,V) = φ(Q) ( φ(K)T V ) / ( φ(Q) · φ(K)T 1 )
分子:先算 d×d 的 φ(K)TV 再查询;分母:对归一化项做同样的结合律变形
  • 复杂度从 O(N²d) 降到 O(N·d²):只需计算三个"序列 → d×d 汇总"的乘积。
  • 分母那项是 softmax 归一化的遗产:把每个查询的权重和归一成 1。代价是分母可能接近 0 造成数值不稳,后续变体各有处理办法(有的干脆去掉归一化)。
  • 严格地说,φ = elu+1 只能近似(而非等价)softmax 核;Performer(FAVOR+)则用随机特征在统计意义上逼近 exp 核。

3. RNN 视角:线性注意力 = 固定大小状态的有穷自动机As a Linear RNN

把上面的"先汇总"路径按因果(每个 token 只看历史)逐位展开,会得到一个惊人的等价形式——线性注意力**就是一个线性 RNN**,它的隐状态是一个 d×d 矩阵 S:

St = St−1 + vt ktT      输出: yt = qtT St
读作:把当前 token 的 (key, value) 外积"写入"外部记忆 S;用 query 去读 S

三种等价的计算排布(现代实现的核心卖点):

模式做法复杂度用途
递归(recurrent)逐 token 更新 S时间 O(N·d²),显存 O(d²) 常数推理生成(天然适合,无需缓存历史)
并行(parallel)直接算 Q(φ(K)ᵀV)/归一化O(N·d²)(配合分块可并行)训练(GPU 友好,无 N×N 矩阵)
分块(chunkwise)块内用并行形式、块间用递归形式两者折中训练实际采用的折衷(如 GLA/GDN 的 kernel)
与 softmax 推理的本质区别:生成第 t 个 token 时,标准注意力要把新 q 与全部 t 个历史 K/V 打分(读的量随 t 线性增长);线性 RNN 只读固定大小的 S(O(d²),与 t 无关)。长上下文下这就是"越写越慢"与"恒速"的区别。
代价预告:d×d 的 S 只有 d² 个数,却要装下任意长历史的信息——这是一个有损压缩器。它把"数据库"降级成了"笔记摘要"。精确回忆的损失是线性注意力所有弱点的根源,§7 详述。

所有变体回答同一个问题:状态 S 怎么写入、怎么遗忘、怎么读出?区别只在递推式的细节:

记忆的四种操作,一张表看完:累加(Linear Transformer)、固定衰减(RetNet)、数据依赖遗忘(GLA/RWKV/Mamba)、覆盖改写(DeltaNet/GDN)。越往后,对"同一事物被多次提及"的处理越合理——人脑改口"我之前说错了"时,需要的正是覆盖而不是叠加。

标准注意力赢在:精确性。它是一个无损的键值数据库;凡是需要"逐字 retrieval"的任务(长文档找细节、代码编辑、 needle-in-a-haystack)仍然是它更强。这是表达能力层面的差距,不是常数项优化能抹平的。

7. 线性注意力的"命门":精确回忆与 Delta RuleRecall vs. Capacity

固定 d×d 状态意味着:全部历史被压进 d² 个数字。当"不同的键值对"数量超过状态容量,必然发生串扰(interference)。两个补救方向:

  • 别乱堆 —— Delta Rule(覆盖式写入):标准线性注意力遇到重复的 key 会把两次的 value 都累加进同一格(旧信息错误地残留)。DeltaNet 引入梯度的"增量更新":先减去该 key 方向上的旧投影,再写入新值——同一 key 再次出现 = 更新记录,而不是叠加。
  • 该忘就忘 —— 门控(Gating):给状态乘一个数据依赖的遗忘门 αt,让模型自己决定哪些记忆整体衰减(Gated DeltaNet 把覆盖与门控结合,公式见 §5 表格最后一行)。

🔥 演示 5 · 状态更新可视化:累加 vs Delta Rule(GDN)

8×8 外部记忆 S 的热图。序列里同一个 key(同一行)会反复出现,每次携带不同的 value。观察两种写入方式的差别:累加模式把新旧 value 越叠越亮直至糊死;Delta 模式(α=0.92, β=1.0)则覆盖旧值、遗忘久远记忆,始终保留"最新记录"。

业界给出的第三个答案最务实:混合(hybrid)——两种都要。既然线性层便宜而全注意力层会精确检索,就让大多数层用线性注意力扛长程"记忆流",少数层用 softmax 注意力做"精确检索锚点"。经验上 15–25% 的全注意力层就能把召回能力拉回接近全注意力水平(Arora et al. 2024;Qwen、Jamba、MiniMax 等均走此路线),同时保住约 85% 的线性层带来的效率收益。

8. 回到 Qwen3.5:为什么是 1×GQA + 3×GDN 的混合Back to Qwen3.5

现在可以完整解读整体框架图里语言模型那一行 “(1×GQA 全注意力 + 3×GDN 线性注意力)×8 组”:

1× GQA 全注意力层(每 4 层 1 个,共 8 个)3× GDN 线性注意力层(共 24 个)
角色精确检索锚点:无损访问任意历史 token长程记忆流:以固定状态廉价地携带全局上下文
状态KV Cache(随 N 增长,但只占 1/4 层数 + GQA 4 头,已经很薄)d×d 递归矩阵(与 N 无关)
占比25%75%
这套混合结构对 Qwen-Drive 的规划专家至关重要:论文与代码(modeling_qwen_drive.py::full_attention_layers)显示,规划专家读取的 8 份 K/V 缓存恰好来自这 8 个 GQA 层(配置项 layers_per_kv = 4:每 4 层里只有那 1 个全注意力层产生缓存)。换言之——专家_conditioning 的正是模型的"精确检索通道"。GDN 层没有可读取的 K/V 缓存,它只有滚动状态。这也解释了为什么采样缓存时按 layer_types == "full_attention" 过滤,而不是按层号取前 8 层。
  • 效率侧收益:75% 的层无 KV Cache 增长 → 驾驶视频多帧序列(逐视角 × 逐时间步,token 数很大)的推理成本被大幅压平;这对车载部署(24GB 级单卡)是实打实的可行性差异。
  • 能力侧保底:8 个全注意力层保住精确回忆能力 —— 对驾驶场景里"几秒前那辆插入的车""交通灯从红变绿"这类需要精确定位的证据,检索通道仍在。

9. FAQ:常见疑问与误解FAQ

Q1:线性注意力是标准注意力的"近似"吗?
分两派:Performer / Random Feature 类是(用随机特征逼近 exp 核);Linear Transformer、RetNet、Mamba、GDN 这类不是近似,是替换——它们定义了新的算子,牺牲精确核换取线性复杂度,再靠门控/delta rule 找回表达能力。

Q2:为什么推理快?不就是训练省了吗?
推理快有两个来源:① 每个新 token 只更新/读取固定大小的 S(O(d²)),而 softmax 注意力要和全部历史打分(O(N·d)),N > d 之后线性注意力更快;② 状态显存恒定,长上下文不会撑爆显存带宽与容量,吞吐恒定。

Q3:那为什么不一刀切全用线性注意力?
因为精确回忆会被固定容量卡死(§7)。全线性模型在 MQAR / needle-in-a-haystack / 长文档问答上明显掉分。混合架构(如 Qwen3.5 的 3:1)是目前效率与能力的主流平衡点。

Q4:线性注意力还需要位置编码(RoPE)吗?
通常不需要传统 RoPE:时间顺序已经由状态的时间演化(衰减/覆盖)隐式编码。这也是为什么笔记 03b 里 M-RoPE 的讨论只涉及全注意力通路——GDN 层吃的是 (t,h,w) 位置信息经过状态动态间接体现的。

Q5:递归模型不是不能并行训练吗?
那是老 RNN 的问题。线性 RNN 的更新对状态是线性的,因此可以矩阵化分块:块内并行(小矩阵乘)、块间接力(结合律),配合 Triton/CUDA kernel 在 GPU 上高效训练(chunkwise 并行,§3 表)。Mamba 的 selective scan 与 GLA/GDN 的 chunkwise kernel 同属此类。

Q6:"门控"的 α、β 都是什么?
αt(遗忘门):对整个旧状态乘的衰减系数,由当前输入决定——"这段历史还有多重要"。βt(写入强度/delta 系数):本次写入在 key 方向上的幅度,"新证据多确信"。两者都是小网络从 token embedding 算出的标量/向量。
