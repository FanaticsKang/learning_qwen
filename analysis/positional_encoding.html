0第 0 章·3'

开场：Attention 为什么需要位置？

打乱 token 顺序，输出为什么不变？

Attention 的计算可以写成一个对所有 token 位置对称的操作：

Attn(X)=softmax(QK⊤d)V,Q=XWQ, K=XWK, V=XWV

如果把输入序列按置换 π 重排，Q,K,V 的行也按同一置换重排，softmax 之后的注意力矩阵只是行列同时置换，输出序列也跟着置换。

这里的 π 是位置集合 {0,…,n−1} 上的一个置换：新序列第 i 位放原序列第 π(i) 个 token；等价地，置换矩阵 P 满足 (PX)i=Xπ(i)。例如 π=[2,0,1] 把 [A,B,C] 变成 [C,A,B]。也就是说：

  • Attention 本身是置换等变的（permutation-equivariant），不是“置换不变”。
  • 没有位置编码时，模型知道“谁和谁相关”，但不知道“谁在前、谁在后”。
  • 位置编码的任务，是把顺序信息注入到本来看不见顺序的计算里。
当前 π = [0, 1, 2, 3]；直接拖动词语可交换位置。位置编码关闭：矩阵只是行列随 token 移动。

widget 下方显示的 π = [...] 就是当前顺序：π(i) 表示第 i 位放的是原序列第 π(i) 个 token。

深入一层：置换等变到底是什么意思？

设输入 X 的行按置换矩阵 P 重排为 PX。由于线性投影逐 token 作用，Q′=PQ、K′=PK、V′=PV。于是

softmax(Q′K′⊤d)V′=softmax(PQK⊤P⊤d)PV=PAttn(X)

输出只是按同一置换重排，没有产生新的顺序信息。只有在对序列做池化、取 CLS、或者接一个不关心顺序的 head 之后，才会进一步变成“置换不变”。

  • 先用 30 秒讲清楚：没有位置编码，Attention 看到的是一个“集合”，不是“序列”。
  • 拖动任意一个 token 到另一个位置：token 方块和矩阵的行列会一起实时移动；松手后看 π 的变化。
  • 再打开“位置编码”开关，重复同一次交换，对比矩阵数值的最大偏差。
  • 一句话结论：Attention 是置换等变的，位置编码负责打破这种对称性。
1第 1 章·8'

正余弦位置编码：给每个位置一个唯一指纹

为什么用不同频率的 sin/cos？

最经典的做法是把位置 p 直接写成一组不同频率的正弦、余弦值：

PE(p,2i)=sin(p100002i/d),PE(p,2i+1)=cos(p100002i/d)

每一对 (2i,2i+1) 可以看成一个二维向量。随着位置 p 增加，这个向量在单位圆上以角速度 ωi=10000−2i/d 匀速旋转。维度越大，频率越低、波长越长；维度越小，转得越快。

L=64，d=64，base=10000。每行是位置 16 的指纹，每列是维度 0 的正弦/余弦序列；维度越大频率越低、波长越长。
  • 不同维度 = 不同频率；每一行是一个位置独有的“指纹”。
  • 相邻位置平滑变化：高频维度负责区分近处，低频维度负责区分远处。
  • 每一对 sin/cos 是一根绕表盘旋转的指针；位置就是角度。
  • PE(p+k) 可以由 PE(p) 经过一个只依赖 k 的分块旋转得到。
深入一层：PE(p+k) 的旋转矩阵推导

对第 i 个频率对，记 θi=ωik。利用和角公式：

[sin(ωi(p+k))cos(ωi(p+k))]=[cosθisinθi−sinθicosθi][sin(ωip)cos(ωip)]

把所有频率对按块对角拼起来，就得到 PE(p+k)=MkPE(p)。这里的 Mk 是一个 d×d 的块对角矩阵，不是单个 2×2 矩阵；第 i 块就是上面的 2×2 矩阵，块内角度为 θi=ωik：

Mk=blockdiag(B0(k),B1(k),…,Bd/2−1(k)),Bi(k)=[cosθisinθi−sinθicosθi]

以 d=4（两个频率对，ω0=1、ω1=0.01）为例：

Mk=[cos(ω0k)sin(ω0k)00−sin(ω0k)cos(ω0k)0000cos(ω1k)sin(ω1k)00−sin(ω1k)cos(ω1k)]

Mk 的元素只含 k、不含 p，所以同一个 M1 同时满足 M1PE(1)=PE(2) 与 M1PE(5)=PE(6)。每个块正交且行列式为 1，因此 Mk 是 d/2 个平面旋转的直和，并满足 MjMk=Mj+k、Mk−1=M−k=Mk⊤——这正是位置编码“可表达相对位置”的来源。

PE 的基序是 (sin,cos)，第 2 章 RoPE 用的是 (cos,sin)，两者只差一个换基 S=[0110]：

B(θ)=SR(θ)S,R(θ)=[cosθ−sinθsinθcosθ]

所以第 1 章的块看起来像“反着转”，实际上是同一个旋转。Mk 在 Transformer 里不会被显式计算：它只说明“存在”；RoPE 则把这个旋转直接作用到 q/k 上。

“正弦位置编码能表达相对位置”说的是存在一个只依赖 k 的线性变换，而不是说 Attention 自动学会用它。实际模型是否利用这个结构，要靠训练。

  • 先看频率阶梯与扫描线，再说清低频/高频分工；点击热力图会自动暂停扫描。
  • 拖动扫描线，选一行看指纹、选一列看正弦曲线、看右下角表盘。
  • 把 p 和 p+k 的指纹并排，指出二者只差一个分块旋转。
2第 2 章·12'

RoPE：把位置变成 q/k 的旋转

正弦 PE 已经能表达相对位置，为什么还需要 RoPE？

2.1 正弦 PE 留下的问题

第 1 节证明了 PE(p+k)=MkPE(p)：位置每增加 k，编码向量就乘上一个只依赖 k 的分块旋转。看起来相对位置已经被解决了。但这是编码层的性质，不是 attention 分数的性质。

Attention 真正看到的是投影后的 q/k：

qp=Wq(ep+PE(p)),kn=Wk(en+PE(n))

记 A=Wq⊤Wk，展开点积：

qp⊤kn=ep⊤Aen+ep⊤APE(n)+PE(p)⊤Aen+PE(p)⊤APE(n)

只有最后一项是“位置×位置”。中间两项是内容×位置交叉项，会随绝对位置 p,n 变化；最后一项看起来最接近相对量，但一般情况下它也不是。

把 PE(p)=MpPE(0)、PE(n)=MnPE(0) 代入最后一项：

PE(p)⊤APE(n)=PE(0)⊤M−pAMnPE(0)

想让两个旋转合并成 Mn−p，中间必须穿过 A：矩阵乘法不可交换，M−pAMn 一般合并不成 AMn−p——除非 A 恰好与每个频率块的旋转矩阵可交换。“与每个频率块的旋转对齐”说的就是这个条件：在每个 2×2 频率块里，A 的那一块必须形如 [a,−b;b,a]（“旋转加缩放”，对应复数乘以 a+bi）；任何反射、剪切或跨频率块的混合都会破坏它。而 A 是学出来的，没有任何机制要求它长成这样。

反例见下方“深入一层”：取 A 交换两个分量（一个反射），PE(p)⊤APE(n) 算出来是 sin((p+n)ω)——依赖 p+n 而不是 n−p，相对性直接被破坏。

所以正弦 PE 的问题不是“没有相对位置”，而是：

  • 相对性只是“可表达”：Mk 只存在于编码里，前向计算中根本不会构造它；模型可以学会利用它，也可以忽略它。
  • 内容和位置相加：交叉项让绝对位置泄漏进 attention 分数；把同一对 token 整体平移，分数一般会变。
  • 加法改变范数：位置项的强度会被后续归一化和投影改变；没有“只改角度、不改长度”的约束。

本节的目标不是“再讲一个位置编码”，而是把相对性从“可表达”变成“必然”：对任意内容 q,k，让 qm⊤kn 只依赖 n−m。

2.2 RoPE：旋转整个 q/k

RoPE 仍然复用第 1 节的频率阶梯，但把“位置变化 = 旋转”这件事从 PE 向量 搬到 q/k 整体：

  • 第 1 节：位置 p 的每个频率对，是单位圆上角度为 pωi 的指针；
  • RoPE：位置 m 的整个 q 旋转 mωi，位置 n 的整个 k 旋转 nωi。

对第 i 个频率块（二维）：

qm,i=Ri(m)qi,kn,i=Ri(n)ki,Ri(ϕ)=[cos(ϕωi)−sin(ϕωi)sin(ϕωi)cos(ϕωi)]

两边都旋转后：

qm,i⊤kn,i=qi⊤Ri(m)⊤Ri(n)ki=qi⊤Ri(n−m)ki

先看清加法 PE 里“位置”以什么形式存在。Wq 是线性投影，可以拆项：

qp=Wq(ep+PE(p))=Wqep+WqPE(p)

前一项只由内容决定，后一项只由位置 p 决定。所谓“加法 PE 不改变内容”是字面意义的：同一个词摆在第 3 个还是第 300 个位置，它贡献的内容分量 Wqep 是同一个向量；换位置只是把位置分量换掉。位置信息以独立加项的形式叠加在内容旁边，两项互不接触。

RoPE 的 qm=R(m)q 没有这种可拆性：旋转作用在整个 q 上，转完之后每个分量都同时含内容和位置，向量里不存在“只装位置”的子空间。同一个内容放在位置 0 和位置 100，得到的 q 方向差了 100ωi 的角度——位置不是外加物，它就是内容向量被转过的角度本身。

可以这样比：加法 PE 是把工牌别在衣服上，人还是那个人，牌子是外挂的；RoPE 是让人换个朝向站，朝向就是位置，身上没多任何东西。

这个差别就是相对性的来源。加法 PE 的旋转结构 Mk 只存在于位置分量内部；一旦做投影和点积，上一节的四项交叉相乘，位置和内容互相污染，绝对位置泄漏进分数。RoPE 把旋转直接作用在参与点积的向量上，R(m)⊤R(n) 在点积里当场合并成 R(n−m)：把 m,n 同时平移 δ，相当于给两个旋转后的向量再叠加同一个旋转 R(δ)，夹角不变，点积也就严格不变——不依赖任何学到的矩阵碰巧可交换。只转 q 或只转 k 时，另一侧没有对应的反向旋转，绝对位置不会被抵消——W3 的“只转 q/k”开关可以直接看到这一点。

把所有频率块按块对角拼起来：

R(ϕ)=⨁iRi(ϕ)

就得到完整的 RoPE。注意：位置调制因子 R(n−m) 只依赖相对距离；完整点积仍然依赖 q、k 的内容。

画面分两半。左边沿用第 1 节的表盘，显示当前 m 和 n=m+Δ 在选定频率槽上的两根指针，夹角就是 Δωi——这是“因”；右边两张热图分别是加法 PE 和 RoPE 的分数 S(m,n)——这是“果”。

热图的读法：横轴是 n（key 位置），纵轴是 m（query 位置），第 m 行第 n 列的颜色就是 S(m,n)。n−m 相同的格子连成一条“对角线”，所以判据只有一条：相对性成立 = 同一条对角线颜色处处相同；绝对位置泄漏 = 同一条对角线上颜色还在随 m 变化。

建议按这个顺序演示：

  1. 保持默认（两边都转），把 Δ 拖到 3，点“播放扫描”，盯住高亮格子沿对角线移动：RoPE 一路等色，加法 PE 的深浅在变。下方读数条是数字证据——“上一步 m=12→13：加法 −0.054→0.137，RoPE −0.209→−0.209”翻译过来就是：绝对位置挪了一格、Δ 没变，加法 PE 的分数动了约 0.19，RoPE 纹丝不动。
  2. 切“只转 q”：RoPE 的对角等色性立刻被破坏——绝对角度必须两侧同转才能在点积里抵消，这也是所有 RoPE 变体都成对旋转 q/k 的原因。
  3. 把 partial rotary 调到 25%（Qwen3.5 的真实配置）：前缀维度保持等色对角线，其余 75% 的维度完全不感知位置——对应第 5 章源码里的 q_rot / q_pass 切分，讲到那里可以拉回来对照。
  4. rope_theta 从 1e7 切到 1e4：大槽号（低频）的指针绕圈明显变快——这是第 6 章长上下文的伏笔，先记住现象即可。
  • 位置没有进入 token embedding；它在 Attention 前旋转 q/k。
  • 两边都旋转时，位置调制因子只依赖 n−m；只转一边，绝对位置仍会泄漏。
  • RoPE 是正交旋转，保范数；正弦 PE 是加法，会改变范数。
  • 高频维度很快绕圈，负责近距离区分；低频维度负责长程。
  • partial RoPE 旋转 head 维的前缀，其余维度完全不感知位置。
深入一层：A 不对齐时，“位置×位置”项也不是相对量

只看一个频率块，PE(p)=[sin(pω),cos(pω)]⊤。取 A=Wq⊤Wk=[0110]（交换两个分量），则

PE(p)⊤APE(n)=sin(pω)cos(nω)+cos(pω)sin(nω)=sin((p+n)ω)

它依赖 p+n，不是 n−p。所以 PE(p+k)=MkPE(p) 并不能保证 attention 分数具有相对性；还需要 A 与旋转群对齐。RoPE 不需要这个条件，因为旋转直接作用在整个 q/k 上。

深入一层：标量展开与内容系数

上面用的是块矩阵写法。对单个频率块，记频率为 ωi，设

Ri(ϕ)=[cos(ϕωi)−sin(ϕωi)sin(ϕωi)cos(ϕωi)]

由正交性 Ri(m)⊤=Ri(−m)，以及旋转的群性质 Ri(−m)Ri(n)=Ri(n−m)，有

qm,i⊤kn,i=(Ri(m)qi)⊤(Ri(n)ki)=qi⊤Ri(n−m)ki

把所有频率块按块对角拼起来，R(n−m) 的每个块只含 n−m，所以位置调制因子只依赖相对位移。展开成标量后，每一项形如

(q2ik2i+q2i+1k2i+1)cos((n−m)ωi)+(q2i+1k2i−q2ik2i+1)sin((n−m)ωi)

相对角只出现在 cos/sin 里，而前面的系数仍由 q、k 的内容决定——这就是“位置调制因子只依赖 n−m，但完整点积仍依赖内容”的矩阵解释。

深入一层：Qwen3.5 的 rotate_half 与频率表

Qwen3.5 的实现不是把相邻两维配成一对，而是把旋转维切成前后两半，配对 (i, i+rotaryDim/2)：

q_rot = q[..., :rotary_dim]
q_pass = q[..., rotary_dim:]
q_embed = q_rot * cos + rotate_half(q_rot) * sin
rotate_half([x1, x2]) = [-x2, x1]

频率表长度为 rotaryDim/2。Qwen3.5 的 head_dim=256、partial_rotary_factor=0.25，所以有效旋转维是 64，频率槽是 32；emb=cat(freqs,freqs) 之后才是 64 个旋转通道。

不要写成“RoPE 让点积只依赖相对位置”。准确说法是：位置调制因子只依赖相对位置；点积还带着内容项。也不要把 RoPE 说成“删掉了绝对位置”：q/k 仍然按绝对位置 m,n 旋转，只是内积让绝对角抵消。

  • 先回到第 1 节的表盘：位置变化对应一次旋转；问一句“这个旋转为什么没有保证 attention 分数只依赖 n−m？”
  • 展开四项：内容×内容、内容×位置、位置×内容、位置×位置；指出中间两项随绝对位置变，而 Wq⊤Wk 没有对齐约束。
  • 把同一个旋转搬到整个 q/k：qm=R(m)q、kn=R(n)k；两边同转，夹角不变。
  • 进 W3：固定 Δ=3，播放扫 m。先看加法 PE 的分数在变，再看 RoPE 的读数不变；对照两张热图的对角结构。
  • 再切“只转 q”，指出绝对位置泄漏；最后把 partial 调到 100%，说明尾部维度完全不感知位置。
3第 3 章·9'

2D RoPE：图像不是一条线

图像 token 是网格，怎么编码行列？

图像 patch 是二维网格。Qwen3.5 的 ViT 用两套位置信息：

  1. 一个可学习的绝对位置表 nn.Embedding(2304, 1152)，48×48，双线性插值到实际网格，直接加到 patch embedding 上；
  2. 一套 2D RoPE：vision head_dim = 72 = 2 × 36；前 36 维是 [row 0..17 | col 0..17]，后 36 维是同一份的复制；每个轴只有 18 个独立频率，rotate_half 配对 (i, i+36)。

最终 cos/sin 是 72 维，配对关系是 (i, i+36)：row 配对 (0,36)…(17,53)，col 配对 (18,54)…(35,71)。

网格
旋转轴
A=(1,1)，B=(3,4)，Δrow=2，Δcol=3，2d 模式偏置=0.819。行和列各用 18 个独立频率，点积按两个轴向分解，没有交叉项。
  • 2D RoPE 不是把二维坐标压成一条 1D 索引，而是 row/col 各占独立子空间、各转各的。
  • 独立子空间意味着点积按 (Δrow,Δcol) 分项相加，没有交叉项。
  • ViT 同时使用可学习绝对位置和 2D RoPE；时间步复用同一套空间坐标。
  • ViT attention 是非 causal 的，但按 temporal patch 分段；跨 temporal patch 没有 ViT 内 attention。
深入一层：72 维到底怎么配对的

Qwen3_5VisionRotaryEmbedding(dim=head_dim//2=36) 产生 18 个频率。rot_pos_emb 为每个 token 返回 36 维 [row 0..17 | col 0..17]，然后

emb = cat(rotary_pos_emb, rotary_pos_emb)   # (N, 72)

rotate_half 对半切，所以维度 i 和 i+36 配对。row 的 18 个频率只和 row 的复制配对，col 同理。不要把 72 讲成“row 36 个独立频率 + col 36 个独立频率”——每个轴只有 18 个独立频率。

可学习绝对位置以加法融合到 patch embedding：hidden_states = patch_embed + pos_embed；2D RoPE 在 attention 内以旋转作用于 q/k。两者并用，不是二选一。

  • 默认 A=(1,1)；点击/拖动选择 B，点“重选 A”后再点网格可改 A，观察 (Δrow,Δcol) 与右侧偏置热图。
  • 切换“只转行/只转列/行+列”，说明独立子空间的可分离性。
  • 切到 13×19，对应真实的 26×38 patch 网格，并说明 spatial_merge_size 只改变 token 打包顺序，不改变 rot_pos_emb 使用的全分辨率坐标数值。
4第 4 章·12'

3D M-RoPE：视频的 (t,h,w)

时间维怎么进 RoPE？

M-RoPE 保留三行 position_ids：t / h / w。它不是一个真正的 SO(3) 旋转，而是三个可分离的 1D 旋转，让每个轴占用互不相交的频率槽。

Qwen3.5 的 mrope_section=[11,11,10] 有 32 个频率槽，总和等于 rotaryDim/2。5.5.4 的实现无条件 interleaved：

  • 先令 freqs_t = freqs[0]（全部取 T）；
  • H 覆写 slice(1, 33, 3)，即槽 1,4,…,31，共 11 个；
  • W 覆写 slice(2, 30, 3)，即槽 2,5,…,29，共 10 个；
  • 剩下 0,3,…,30 共 11 个留给 T。

所以前 30 个槽是 (THW)×10，最后两个槽依次是 T、H；T/H/W = 11/11/10。不是把三行连续分块的 TTT…HHH…WWW，也不是 THW 重复到 32 个槽。源码 docstring 写 …TT，与代码实际结尾 …TH 不一致。

布局
token 类型
M-RoPE 是三个可分离的 1D 旋转，t/h/w 各占不相交的频率槽；当前布局 interleaved，槽数 11/11/10。Qwen3.5 的实现固定为 interleaved：每个轴同时拿到高低频。

打开“自动旋转”可让立方体缓慢旋转；拖拽会暂停自动旋转。

  • M-RoPE 是三个可分离的 1D 旋转，各占不相交频率槽；不是 SO(3) 旋转。
  • 文本 token 三行同值，退化为标准 1D RoPE。
  • 视频段内 t 恒定；h/w 相对 current_pos 生成。
  • interleaved 让每个轴同时覆盖高低频、频谱更均衡；源码 docstring 称之为 preserving frequency continuity，但按代码更准确的说法是“频谱均衡”，而不是相邻频率索引连续。

4.1 Qwen3.5 的视频时间戳：3D 的壳，2.5D 的里

演示模式下本章默认显示 3D 立方体；按 T 或点“备用图”切换到视频时间戳实验室。

Qwen3.5 复用 Qwen3VLProcessor。视频里每个 temporal patch（2 个采样帧）对应一个 <X.X seconds> 时间戳：

<0.5 seconds><|vision_start|> ... 247 video tokens ... <|vision_end|>
<2.5 seconds><|vision_start|> ... 247 video tokens ... <|vision_end|>

get_rope_index 先把 video_grid_thw[:,0] 展开成 T 个 [1,H,W] 段，再对每段生成 (t,h,w)：

  • 段内 t = current_pos 恒定；
  • h = current_pos + 0..llm_h-1，w = current_pos + 0..llm_w-1；
  • 段后 current_pos += max(H,W)//spatial_merge_size；
  • 段与段之间还有 vision_end、时间戳文本、vision_start，它们也逐个推进 current_pos。
版本
共 2 个 temporal patch（每段 2 个采样帧），515 token。P0 的 t=10，P1 起点 t=37（+19+1+时间戳+1=27），mrope_position_delta=-456。时间戳是 6/6 个 token；真实秒数不进入 RoPE。

深入一层：Qwen2.5 的 second_per_grid_ts 与 5.5.4 的差异

Qwen2.5 processor 计算 second_per_grid_ts = temporal_patch_size / sampled_fps，设计意图是用 time_interval = tokens_per_second * second_per_grid_ts 给 temporal 位置定标；5.5.4 的实际写法是 tokens_per_second * int(second_per_grid_ts)。但本机 5.5.4 的 modeling_qwen2_5_vl.py 把整段视频的 t 设成 start * time_interval（整段常数），与同文件 docstring 的“逐 patch 递增”矛盾；疑似重构回归，未在 4.x 逐字节验证。因此本材料只讲 Qwen2.5 的设计意图，位置 ID 演示以 Qwen3.5 为准。

  • 先看 3D 立方体：三个轴、三个槽带，强调“不是 SO(3)”。
  • 按 T 切到视频实验室（本章第二张图）：默认就是 515-token 例，指认 t=10、t=37、+19、delta=-456。
  • 把时间戳切到 <100.0 seconds>，指出总 token 数变化来自 8 个 token 的文本。
  • 最后强调：真实秒数不在 RoPE 里，这是“2.5D”的含义。

Qwen3.5 源码深挖：RoPE 到底覆盖了多少

真实模型到底怎么算？

Qwen3.5 的 LLM 主干是混合架构：每 4 层是 GDN, GDN, GDN, GA。只有 GA（full_attention）层消费 position_embeddings；GDN 层没有 RoPE，顺序信息来自 causal depthwise Conv1d(kernel=4) 和 gated delta rule 的递推状态。

hidden_size 5120 4096

num_attention_heads (Q) 24 16

GQA group 6:1 4:1

rope_theta 1e7 1e7

  • 9B：32 层中 8 层 GA；GA 层内同样是 64/256。
  • ViT 27 层全部有 2D RoPE；LLM 主干的“只有 1/4 层”不能外推到整个模型。
  • 两个 1/4 不能相乘当作全模型比例：GDN 层根本没有 256 维 attention head。
深入一层：head_dim 不能由 hidden_size 反推

27B 的 24×256=6144≠5120，所以 hidden_size / num_attention_heads 不是 head_dim。head_dim 是 config 显式字段。9B 的 16×256=4096 恰好等于 hidden，但也只是巧合，不能拿来当规则。

深入一层：flash_attention_2 与 include_vit

在 LLM 主干内，flash_attention_2 只落到 GA 层；但 ms-swift 设置 attn_impl 时使用 include_vit=True，ViT 的 27 层也会使用同一个 attention 实现。所以“flash attention 只作用于 1/4 层”只在 LLM 主干内成立。

深入一层：MTP 层不计入 64/32 层时间线

checkpoint 可能带 mtp.layers.0；HF 实现用 _keys_to_ignore_on_load_unexpected = [r"^mtp.*"] 忽略它。层时间线与“16/64、8/32”的统计都不包含 MTP。

  • 切 9B/27B，指出 64/32 与 16/8 两列数字同步变化。
  • 悬停某一层：GA 显示旋转维，GDN 显示“无 RoPE，靠 conv + recurrence”。
  • 切到 ViT 视图：27 层全部有 2D RoPE，和 LLM 的 1/4 形成对比。
  • 最后提醒：不要把两个 1/4 相乘。
6第 6 章·4'

长上下文简析：theta、PI、NTK、YaRN

rope_theta=1e7、NTK、YaRN 在做什么？

RoPE 的频率决定“多远还算得清”：高频项转得快，远距离会绕很多圈；低频项转得慢，负责长程。长上下文扩展本质上是在改频率或改位置索引：

  • 增大 theta：拉长所有波长，但会牺牲近距离分辨率；不是单调收益。
  • PI（位置插值）：位置索引统一除以 s，等价于所有 θi 除以 s；需要微调。
  • NTK-aware：改 base，b′=b·sd/(d−2)。注意 d 是实际旋转维度（Qwen3.5 是 64），不是完整 head_dim=256。
  • YaRN：NTK-by-parts + attention temperature；原版最佳结果需要少量微调，不是“完全免微调”。
  • Qwen3.5 的 rope_type="default"，没有启用 YaRN / LongRoPE / 线性缩放。
  • max_position_embeddings=262144 是声明上限，不是 RoPE scaling 的结果。
  • 外推不是免费的：改频率会改变模型在预训练时学到的相对位置结构。
  • 常见误区：RoPE 天然外推；theta 越大越好；PI 就是调大 theta；NTK 就是位置插值。

rope_theta=1e7 是预训练超参，不是“为了让 256K 上下文而开的开关”。不要把 max_position_embeddings 当成“模型一定能在该长度上保持同等质量”的保证。

  • 先看波长阶梯：低频维度负责长程，高频维度负责近处。
  • 拉长序列，看相对位置热图如何塌缩；再切 PI/NTK 看恢复。
  • 强调 Qwen3.5 本身是 default；这一章是“方法与代价”，不是“Qwen3.5 用了哪个”。

速查与常见追问

一句话怎么答？
  • Attention 是置换等变的；没有位置编码就没有内在顺序。
  • 正余弦 PE 是加法式；RoPE 在 Attention 前旋转 q/k；位置调制因子只依赖相对距离。
  • 2D RoPE 行/列各占独立子空间；ViT 72 维 = 18 row + 18 col，再复制。
  • M-RoPE 是三个可分离的 1D 旋转；mrope_section 分配的是 32 个频率槽，cat(freqs, freqs) 之后才是 64 个旋转通道。
  • Qwen3.5：1/4 的层是 GA、GA 层内 1/4 的 head 维旋转，ViT 27 层全部有 2D RoPE；视频每个 temporal patch 一段，时间戳 6/7/8 token，stride=27/28/29。
